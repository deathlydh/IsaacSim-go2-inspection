# План: заводской цех, камера на Go2, нормальная походка

Обозначения: **[проверено]** — подтверждено в живой сессии, по исходникам или по файлу. **[оценка]** — расчёт без измерения. **[не проверено]** — подтвердить не удалось.

## 0. Исходное состояние и краткий словарик для новичка

**Что есть сейчас:**
- **Сцена.** Файл `D:/go2-inspection/scenes/inspection.usd` создаётся скриптом `tools/isaac/build_scene.py`. В нём два объекта: `/World/ground` (пол-сетка Grid default_environment со своим светом) и `/World/Robot` (go2.usd). `start_go2.py` при каждом запуске заново открывает эту сцену (строка 116).
- **Производительность.** Около 38 FPS. Упор в физику на CPU: кадр 25.5 мс, из них физика около 12 мс. GPU загружен примерно на 36 %.
- **Видеопамять.** Занято 3.9 из 8 GB, но в эту цифру входят ещё Unity Editor, Chrome и Discord. В Isaac включена подгрузка текстур по мере надобности (texture streaming) с бюджетом 60 % VRAM.
- **Походка (измерено):**
  - высота корпуса стоя 0.229 м сразу после сброса и 0.200 м после ходьбы; на 0.5 м/с — 0.148 м, на 1.0 м/с — 0.125 м;
  - для сравнения: поза по умолчанию даёт 0.318 м, у реального Go2 около 0.30 м;
  - ступни не отрываются от пола (меньше 1.2 мм) и скользят;
  - частота шага 3.4–4.3 Гц, у реального Go2 около 2 Гц;
  - бёдра разведены, задние ноги волочатся.
- **Причина [проверено]:**
  - Так обучена сама политика: в наградах нет высоты корпуса, отрыва ступней и штрафа за скольжение.
  - Модель привода «мягкая» (kp=25) и проседает на 0.2–0.4 рад под весом.
  - Запуск в Isaac полностью совпадает с обучением: привод DCMotor kp 25 / kd 0.5, физика 200 Гц, политика 50 Гц, тот же порядок суставов.
  - Поэтому настройками это не исправить, нужна другая политика.

**Словарик:**
- **Prim** — любой объект сцены (`/World/Robot/base`).
- **Xform** — prim-«узел» с положением и поворотом.
- **Reference (ссылка)** — подключение чужого USD-файла внутрь своей сцены без копирования. Свои изменения (overrides) хранятся в своём файле.
- **Collider** — форма для физики. Без неё робот провалится сквозь объект.
- **Render product** — отдельный «рендер» для камеры. Каждый стоит VRAM и время GPU.
- **Policy (политика)** — нейросеть, которая 50 раз в секунду по наблюдениям (скорости, углы суставов, команда) выдаёт целевые углы суставов.
- **Binding** — описание того, в каком порядке и масштабе подавать наблюдения в сеть.

**Порядок работ:** 1) цех (без скачиваний), 2) камера и второе окно, 3) походка: сначала A (гигиена), затем C и B (готовые политики, сравнение), D — переобучение, только если понадобится.

**Важно про ассеты SimReady [проверено]:**
- По умолчанию у них включён вариант `Physics='physics'`. Это подвижное тело: бак уедет, если робот его толкнёт.
- Вариант `'none'` убирает подвижность, но коллайдеры остаются типа SDF. Работает ли SDF при физике на CPU — **[не проверено]**.
- Поэтому в своей сцене дополнительно переопределяем `physics:approximation`: `convexHull` для баков и бочек, `convexDecomposition` для ограждений, `none` для труб.

**Манометры делаем сами (процедурно)**
- **Почему не готовые.** В библиотеке нет манометра с отдельной стрелкой. У SimReady `Pressure_Dual_Gauge_Tester_A01` и `Service_Tool_Gauge_Tire_Pressure_Dial_A01` стрелка нарисована на текстуре, показание не меняется. Они годятся только как отвлекающие объекты.
- **Скрипт `tools/isaac/make_gauge.py`:**
  1. PIL или matplotlib (уже есть внутри Isaac) рисует PNG циферблата: дуга 270°, деления, шкала, красная зона, без логотипов.
  2. Циферблат кладётся на диск с материалом UsdPreviewSurface.
  3. Стрелка — отдельный prim под Xform-шарниром, скрипт поворачивает её на нужный угол.
  4. Добавляются корпус-цилиндр и стекло.
  5. Значение, угол, мин/макс и положение центра пишутся в JSON. Это готовая эталонная разметка для CV.
- **Образец.** Тот же принцип проверен на офисных часах `SM_Clock_A`: циферблат 0.30 м и отдельные стрелки `SM_Clock_A_Hour` и `_Minute` [проверено].
- **Параметры.** 5 штук, диаметр 100–160 мм, центр на высоте 0.3–1.0 м (почему так низко — см. часть 2), крепление на трубах и баках.

**Свет.** В зале уже есть 18 RectLight. По желанию можно добавить DomeLight с промышленной HDRI-панорамой Poly Haven (нужно скачивание).

### FPS и VRAM (RTX 4060 Ti 8 GB) [оценка]
- **VRAM:** +0.5–1 GB. Подгрузка текстур ограничена бюджетом, поэтому при нехватке памяти текстуры станут размытыми, а не будет вылета.
- **Регулятор памяти:** `/rtx-transient/resourcemanager/texturestreaming/memoryBudget`. Ключа `textureMipCountBudget`, который советует skill по диагностике, в 6.1 нет.
- **FPS:** с 38 примерно до 32–38. Узкое место — физика на CPU, а робот касается только пола. GPU в запасе, но 18 источников света в режиме RealTimePathTracing его нагрузят.
- **Совет:** закрывать Unity Editor на время симуляции, он делит те же 8 GB.

- Неоднозначность лицензий NVIDIA (для учебного проекта не мешает).
- SDF-коллайдеры SimReady на CPU — обходим переопределениями.
- Первая загрузка из облака долгая.
- По облику это склад; на завод он будет похож только за счёт обвязки.

## 2. Камера на роботе и второе окно

### Рекомендуемый вариант: штатная передняя камера Go2 по официальному URDF
- **Родитель:** `/World/Robot/base`. Не `base/visuals`: этот prim помечен instanceable, добавлять в него дочерние объекты нельзя.
- **Крепление:** `/World/Robot/base/front_camera` — Xform в осях корпуса (x вперёд, z вверх), смещение `(0.32715, 0.0, 0.04297)`. Значение из официального `unitreerobotics/unitree_ros/robots/go2_description/urdf/go2_description.urdf` (BSD-3). В go2.usd от IsaacLab камеры нет [проверено].
- **Сама камера:** `/World/Robot/base/front_camera/rgb` — RtxCamera с локальным поворотом wxyz `(0.5, 0.5, -0.5, -0.5)`. USD-камера по умолчанию смотрит вдоль −Z, этот кватернион разворачивает её вперёд по +X робота [проверено матрицей].
- **Параметры объектива** — по реальной калибровке `go2_ros2_sdk/calibration/front_camera_720.yaml`: 1280×720, fx 864.4, отсюда горизонтальный угол обзора 73° и вертикальный 45.2°. Рекламные «120°» — не угол обзора идеальной камеры без дисторсии, его не берём.
- **Отсечение:** ближнее 0.02 м (объектив на 3–5 мм внутри корпуса головы), дальнее 100 м.
- **Частота:** 10 Гц (делит 50 Гц цикла без остатка). Данные: `rgb`; по желанию `distance_to_image_plane` (глубина) для отладки и эталона. У реального Go2 спереди одна камера без глубины.
- **Второе окно:** 640×360.
- **API 6.1 [проверено по исходникам]:** `isaacsim.sensors.experimental.rtx` (RtxCamera + CameraSensor). Старый `isaacsim.sensors.camera.Camera` устарел с версии 6.0, его не используем.

```python
import sys, omni.usd
from pxr import UsdGeom
from isaacsim.sensors.experimental.rtx import RtxCamera, CameraSensor
from isaacsim.core.rendering_manager import ViewportManager
stage = omni.usd.get_context().get_stage()
mount = UsdGeom.Xform.Define(stage, "/World/Robot/base/front_camera")
UsdGeom.Xformable(mount).AddTranslateOp().Set((0.32715, 0.0, 0.04297))
cam = RtxCamera("/World/Robot/base/front_camera/rgb", tick_rate=10.0)
cam.set_local_poses(translations=[[0, 0, 0]], orientations=[[0.5, 0.5, -0.5, -0.5]])
cam.camera.set_apertures(horizontal_apertures=36.0, vertical_apertures=20.25)  # обёртка умножает на 10
cam.camera.set_focal_lengths(24.31)            # fx = 864.4 px при 1280, HFOV 73 град
cam.camera.set_clipping_ranges(0.02, 100.0)
sensor = CameraSensor(cam, resolution=(720, 1280), annotators=["rgb", "distance_to_image_plane"])  # (H, W)
win = ViewportManager.create_viewport_window(camera="/World/Robot/base/front_camera/rgb",
                                             title="Go2 Front Camera", resolution=(640, 360))  # (W, H)
sys._go2_front_camera, sys._go2_cam_window = sensor, win   # ссылки ОБЯЗАТЕЛЬНО сохранить
# во время Play: rgb, _ = sensor.get_data("rgb"); img = rgb.numpy() if rgb is not None else None
```

### Шаги
1. В `start_go2.py` после `runner.spawn()` и до `timeline.play()` создать камеру, сенсор и окно. Ссылки хранить в `Go2Session`. Иначе сборщик мусора удалит render product: `isaacsim_send` выполняет скрипт внутри функции, и её локальные переменные исчезают после завершения.
2. В `Go2Session.close()` порядок такой:
   1. `ViewportManager.destroy_viewport_windows(include=["Go2 Front Camera"])`;
   2. сбросить ссылку на сенсор;
   3. `timeline.stop()` и 10 кадров ожидания (правило из CLAUDE.md);
   4. `open_stage`.
3. Камеру в `.usd` сцены не сохранять, она создаётся при каждом запуске.
4. **Проверка:** Play → подождать несколько кадров → `get_data("rgb")` → сохранить PNG в `shots/` → замерить FPS через `measure_fps.py`.
5. Если стрелки манометров на картинке размыты, попробовать отключить DLSS или сглаживание только для render product камеры (`omni:rtx:post:aa:op`, `omni:rtx:post:dlss:execMode=quality`). Сейчас включён DLSS Performance. Эффект **[не проверено]**.

**Как то же сделать руками в интерфейсе:**
- Выделить `/World/Robot/base` → правая кнопка → Create > Camera.
- Window > Viewport > Viewport 2 → в меню камеры нового окна выбрать робо-камеру.
- Или Tools > Sensors > Camera Inspector → Create Viewport.

### Альтернативы

### Видимость (влияет на расстановку манометров)
- Камера сейчас примерно в 0.24–0.27 м от пола, потому что робот присел. У реального Go2 около 0.35 м [оценка].
- При вертикальном угле ±22.6° без наклона верхний край кадра на расстоянии d находится примерно на высоте 0.25 + 0.42·d: 0.67 м на 1 м, 1.08 м на 2 м.
- Размер 100-мм циферблата в 720p: 86, 43 и 29 px на расстоянии 1, 2 и 3 м. Надёжно считывать можно примерно от 80–100 px.
- Вывод: точки осмотра около 1 м от прибора, манометры на высоте 0.3–1.0 м, диаметр 100–160 мм.

### FPS и VRAM [оценка]
- Около +0.2–0.5 GB на один render product 720p.
- Окно — это второй render product той же камеры. Оно рендерится каждый кадр, ограничение 10 Гц на него не действует. Поэтому окно 640×360 и закрывать, когда не нужно.
- Ожидаемо минус несколько FPS.
- Общий бюджет вместе с цехом около 5–6.5 GB из 8.

### Риски и ловушки
- **Единицы:** `set_focal_lengths(24)` без задания апертур даёт телевик с обзором 5° [проверено]. Пример в `isaac-camera/SKILL.md` содержит эту ошибку.
- **Порядок размеров:** CameraSensor принимает (H, W), ViewportManager — (W, H).
- **Ориентация:** параметр `orientations=` в конструкторе трактуется как мировой поворот, поэтому вызываем `set_local_poses` явно.
- **Пустые кадры:** `get_data` возвращает None до первых кадров и только во время Play. Данные лежат на GPU, нужен `.numpy()`.
- **Тряска:** камера на корпусе трясётся при ходьбе, снимать манометры только на остановке.
- **ROS 2 на будущее:**
  - кадры `front_camera` и `front_camera_optical` (rpy −π/2, 0, −π/2);
  - мост ROS 2 на Windows не включён по умолчанию;
  - транспорт `rmw_zenoh_cpp` требует заранее запущенного zenoh-роутера;
  - инструкции Pixi рассчитаны на Windows 11, на Win10 **[не проверено]**.

### 3.1 Вариант A — «гигиена» (15 мин, без скачиваний). Присед НЕ исправит

### 3.2 Рекомендуемый вариант C — политика robot_lab для Go2 из rl_sar
Это лучший готовый шанс на естественную рысь. Нужно разрешение на скачивание 0.77 MB.
- **Файлы:** https://github.com/fan-ziqi/rl_sar/tree/main/policy/go2/robot_lab — `policy.pt` (769 376 байт, TorchScript) и `config.yaml` (1 881 байт), плюс `policy/go2/base.yaml`. Лицензия Apache-2.0 [проверено].
- **Почему именно она.** При обучении награды прямо формировали диагональную рысь:
  - `feet_gait` 0.5 (пары ног FL-RR / FR-RL);
  - `air_time_variance` −1;
  - `feet_slide` −0.1;
  - `joint_mirror` −0.05;
  - `feet_height_body` −5;
  - `stand_still` −2.
- **Входы и выходы [проверено по конфигу]:**
  - 45 входов без линейной скорости: угловая скорость ×0.25, вектор гравитации, команды, (q − поза по умолчанию), скорости суставов ×0.05, прошлое действие.
  - Суставы сгруппированы по ногам FR, FL, RR, RL. У нас они идут по типам (все бёдра, потом все колени и т.д.), поэтому нужна точная перестановка.
  - Поза по умолчанию `[0, 0.8, −1.5]` для каждой ноги; масштаб действий `[0.125, 0.25, 0.25]`; шаг физики 0.005 с, политика каждые 4 шага.
- **Реализация без правки Isaac Sim:** своё описание входов через `PolicySpec(binding=...)` (образец — `bundled/franka.py`) и локальная копия env.yaml (бёдра 0, задние бёдра 0.8, kp 25; kp 20 — для сравнения).
- **Шаги:**
  1. Скачать в `assets/third_party/rl_sar_go2/` вместе с LICENSE.
  2. Прочитать граф TorchScript (`torch.jit.load(...).code`) до запуска.
  3. Написать binding и env.yaml, посчитать sha256.
  4. Сделать отдельный стартовый скрипт и провести сравнение (3.4).
- **Риски:**
  - Неизвестны версия Isaac Lab и kp, с которыми обучен файл (20 или 25).
  - Ошибка в перестановке суставов приведёт к падению.

### 3.3 Альтернатива B — Rough-политика Go2 из библиотеки NVIDIA (без сторонних скачиваний)
- **Файл:** `<assets_root>/Isaac/IsaacLab/PretrainedCheckpoints/rsl_rl/Isaac-Velocity-Rough-UnitreeGo2_physx_none_rsl_rl.pt` (6 882 293 байт, sha256 `f15732c6…9570`).
- **Лицензия:** по Model Card v1.1 — BSD-3 (часть под Apache-2.0), коммерческое использование разрешено, только для симуляции [проверено].
- **Формат:** сырой чекпоинт rsl_rl (итерация 1499), сеть 235→512→256→128→12, активация ELU, без нормализатора. Перевод в TorchScript встроенным torch 2.11 проверен в памяти: выходы совпадают, файл получается около 1.16 MB.
- **Входы:** 235 = 48 стандартных + 187 точек карты высот (сетка 17×11). На ровном полу подаём синтетическую карту `np.full(187, base_z − floor_z − 0.5)` с ограничением [−1, 1]. Политика к ней почти нечувствительна: цели коленей меняются меньше чем на 0.06 рад [проверено офлайн].

- **Локальный physx_env.yaml:** пределы моментов hip/thigh/calf = 23.7 / 23.7 / 45.43 Н·м, пределы скорости 30.1 / 30.1 / 15.70 рад/с. Значения выведены из исходников Isaac Lab 3.0 EA, не доказаны. kp 25 / kd 0.5 не меняются.
