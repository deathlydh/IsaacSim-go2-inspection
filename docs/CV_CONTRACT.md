# Контракт CV и данных, версия 1

Дата: 2026-11-05. Независимый Python, без импортов Isaac/Kit в `cv`.

## Датасет

`data/gauges/<run_id>/images/<sample_id>.png`, рядом `manifest.jsonl` (UTF-8,
без BOM). Пути `image_path` относительны каталогу manifest. Одна строка JSON
на сохранённый RGB-кадр. `run_id` — UTC-время + случайный суффикс; `sample_id`
уникален внутри запуска. Существующие каталоги/файлы не перезаписываются.

Обязательные поля строки:

```json
{
  "schema_version": 1,
  "sample_id": "example_0001",
  "image_path": "images/example_0001.png",
  "gauge_id": "Gauge_01",
  "seed": 101,
  "split": "dev",
  "calibration": {
    "vmin": 0.0, "vmax": 10.0, "unit": "bar",
    "start_angle_deg": 225.0, "direction": "clockwise", "sweep_deg": 270.0
  },
  "capture": {
    "pose": {"position_m": [0, 0, 0.3], "quaternion_wxyz": [1, 0, 0, 0]},
    "intrinsics": {"fx": 864.4, "fy": 864.4, "cx": 640, "cy": 360,
                   "width": 1280, "height": 720},
    "timestamp_utc": "2026-11-06T00:00:00Z", "frame_id": 1,
    "light": {"description": "baseline"}, "source": "isaac"
  },
  "truth": {"value": 6.4, "readable": true}
}
```

`split`: `dev` или `test`, определяется по seed и условиям до настройки CV.
`capture.source`: `isaac`, `synthetic_2d` или `saved_image`; происхождение всегда
видно в отчёте. Неизвестные параметры старого кадра — `null`, не выдуманные значения.
`truth.value` — число либо null для отсутствующего прибора; `readable` — булево
или null при отсутствии проверки человеком. Необязательны `truth.bbox`
([x, y, width, height] в пикселях), центр и геометрия стрелки. Эти данные
предназначены только для разметки и оценки после предсказания.

Угол задан в плоскости изображения: 0° вправо, 90° вверх (ось изображения y
направлена вниз). Направление `clockwise` уменьшает угол. Для существующего
`make_gauge.py`: 225° при vmin, -45° при vmax, sweep 270°. Вход CV — массив
RGB uint8 H×W×3 и статическая калибровка. Необязательный ROI задаётся явно;
оценка с известным ROI и полный поиск считаются отдельно. После `cv2.imread`
обязателен перевод BGR → RGB. Текущее значение, угол и геометрия стрелки из
симулятора не передаются алгоритму. ID приходит из задания на осмотр.

## Результат

```json
{"gauge_id":"Gauge_01", "value":null, "unit":"bar", "bbox":null,
 "confidence":0.0, "read_status":"not_found", "error":"dial_not_found"}
```

`read_status`: `ok`, `unreadable`, `not_found`. Только `ok` допускает числовое
значение; отказ всегда содержит `value=null` и объяснение `error`. Успех содержит
`error=null`. `confidence` в [0, 1] — эвристическая оценка, не вероятность.
Координаты bbox относятся к исходному кадру; дополнительные диагностические
поля разрешены. Пороговый статус `normal|warning|alarm|unknown` вычисляется
отдельно по конфигурации с единицами; при отказе он `unknown`.

## Время и движение

Таймауты задаются в секундах настенных монотонных часов. Достижение позы возвращает
`reached|timeout|cancelled|failed`, фактическую конечную позу, ошибки позиции/курса,
длительность и причину отказа. Только reached + проверенная стабилизация + свежий
кадр считаются осмотром. Во всех путях выхода команда обнуляется. Кадр сохраняется
из полученного массива; повторное чтение буфера при записи запрещено.

## Проверенное окружение и команды

Python 3.12.8, OpenCV 4.10.0, NumPy 2.5.2, Pillow 12.2.0.
Зависимости отдельно в `requirements-cv.txt`; ничего не установлено и Python Kit
не изменён. Для проверок используется встроенный unittest.

```powershell
cd D:\go2-inspection
python -c "import cv, cv2, numpy, PIL; print(cv2.__version__, numpy.__version__, PIL.__version__)"
python -m unittest discover -s tests -v
```

Метрики включают все кадры, долю отказов рядом с MAE успешных чтений,
нормированную MAE и долю уверенных ошибок. Test-список и настройки сохраняются
перед оценкой. Цель 2%/95% не является результатом измерения.

## Дополнения R0/A3 (2026-11-06)

Control time в Isaac — сумма physics dt; в нём считаются интегратор и окно
стабилизации. Все таймауты/watchdog — monotonic wall time. UTC служит для журнала,
не для управления. Параметр settle_window_s теперь означает секунды control time.

capture дополнен capture_id, requested_control_s, control_timestamp_s,
received_monotonic_s, timestamp_source, camera_world_matrix_row_vectors,
extrinsics относительно base и virtual_rig. При вариации камеры записываются
фактические extrinsics, а не исходное крепление. pose содержит quaternion_wxyz.
USD-поза фиксируется при получении; синхронизация экспозиции аппаратным timestamp
не заявляется. RGB сохраняется из возвращённого массива.

Первый набор использует виртуальную камеру на существующем render product:
робот физически стоит в 2.2 м от циферблата, камера варьирует дистанцию/курс перед
корпусом. Это синтетические кадры Isaac; не физически проверенная установка камеры.
После изменения значения/света/позы камера остаётся активной, ждём >=0.5 physics s
и 5 render events, затем отдельный fresh capture. Показания/свет/камера/видимость
восстанавливаются в finally. Исходная USD на диске не сохраняется.

split_plan.json создаётся до кадров; seed и условия разделены. Данные с
validation.json valid_for_evaluation=False запрещены для оценки, даже если PNG
и JSON структурно корректны. Отказы CV на корректно захваченных кадрах сохраняются
в метриках и не используются как причина удаления трудных изображений.
